## P1 findings — core package and shipped tooling

### A01 — Encryption staging follows attacker-controlled symlinks

Source: `insideLLMs/privacy/encryption.py:35–39,68–72`.

The direct encryption/decryption APIs open predictable sibling `.enc.tmp` and
`.dec.tmp` paths with `wb`. A precreated symlink redirects truncation, writes and
chmod to another file. Replacement subsequently moves the link itself over the
source path. Concurrent operations also share a staging pathname.

**Proof:** both operations overwrote a synthetic sentinel outside their input
file, changed its mode from 0644 to 0600, and left the source as a symlink.
Decryption put synthetic plaintext into that sentinel.

**Precondition:** another actor can create the staging pathname, and the process
can write the target. The CLI export wrapper's random outer staging narrows
exposure; this finding is not a claim that every CLI export is exploitable.

**Fix:** exclusive unpredictable temporary files, descriptor-based permissions,
and atomic replacement with owned-file cleanup. Test hostile links, concurrent
operations and failure cleanup without touching unrelated files.

### A02 — Ordinary OCI publication can include files outside the run

Source: `insideLLMs/publish/oras.py:67–76`;
`insideLLMs/runtime/_ultimate.py:264`.

The raw publisher forwards paths discovered by `os.walk` to ORAS without a
contained no-follow snapshot. File symlinks enter that list. The stricter
`publish_verified_run` path protects against this, but ordinary/automatic
publication still uses the raw path.

**Proof:** a fake ORAS client received and read a supplied path resolving to a
synthetic external sentinel. No network or real SDK upload occurred.

**Precondition:** an actor can modify the publication input and the publishing
process can read the outside target. This is a filesystem scope problem even
when the caller deliberately chooses structural-only attestations.

**Fix:** share a contained, no-follow immutable snapshot across publication paths;
define an explicit policy for any legacy records alias. A precheck followed by
an ordinary path read is still race-prone. Test links, special files and swaps.

### A03 — Alternate diff action compares the candidate with itself by default

Source: `.github/actions/diff-gate/action.yml:12–15`;
`.github/actions/diff-gate/diff-gate.sh:7,21–44`.

The action describes an omitted baseline as the PR base, but passes an empty
value. Its shell script never resolves the PR base SHA, so both harness runs
execute the current checkout. Deterministic regressions can pass unchanged.

**Proof:** running the actual script with disposable stub commands and a supplied
PR event produced zero Git invocations and two equivalent harness invocations,
differing only in output directory; exit 0.

**Scope:** this is the alternate reusable action, not the repaired root action.
No current repository workflow invoking the alternate action was found. It is
still callable. Additionally, its evaluated code receives `GITHUB_TOKEN`; risk
depends on caller-granted permissions, unlike the repaired split workflow.

**Fix:** remove/deprecate this duplicate or forward to the maintained action.
Otherwise resolve and assert the intended revisions and separate commenting
credentials from candidate execution. Test omitted-baseline PR behavior.

### A04 — Aggregate scoring can fail after a healthy manifest and publication

Source: `insideLLMs/runtime/_sync_runner.py:803–844`, equivalent async lifecycle;
`insideLLMs/runtime/_high_level.py:559,923–926`.

Both runners mark artifacts complete/healthy and reach ultimate processing before
aggregate scoring. If individual calls succeed but `probe.score` raises, the
exception is unwrapped, the manifest stays healthy, and partial diagnostics are
not carried through the harness's typed interruption path. Earlier completed
harness cells can be lost from the returned result.

**Proof:** sync and async runs with an intentionally failing aggregate scorer
left complete/healthy manifests and no partial payload. A mocked ultimate
boundary ran before scoring failed. A two-cell harness lost its partial payload
when the second cell's scorer failed. No actual publication was attempted.

This is distinct from the repaired preservation of a *secondary* scoring failure
after an item-level abort: here aggregation is the first failure.

**Fix:** finish scoring before declaring success or publishing. Convert aggregate
failure into a typed interrupted result retaining raw items, prior cells and
original cause. Test first and secondary aggregation failures in both runners.

### A05 — T-tests report false significance for small samples

Source: `insideLLMs/analysis/statistics.py:1286–1292,1370`.

Welch and paired t-tests use a normal CDF instead of the Student-t distribution;
Welch computes degrees of freedom but does not use them for its p-value.

**Proof:** `paired_t_test([1,2,3], [0,0,0])` returns p = 0.0005320055 and
`significant=True`. The exact two-sided Student-t result for df = 2 is
`1 - sqrt(6/7)` = 0.0741799002, which is not significant at 0.05.
`welchs_t_test([1], [2])` raises `ZeroDivisionError`.

**Fix:** use validated Student-t tail probabilities with the correct degrees of
freedom, and reject insufficient/nonfinite samples explicitly. Add reference
values near decision thresholds, not only range and broad-significance tests.

### A06 — Matched-compute token assurance compares declarations, not execution

Source: `insideLLMs/analysis/matched_compute.py:109–118,273–274,591–605`.

Declared output caps are recorded without binding them to client generation
parameters. Matching checks call counts and model identity but not observed
output-limit violations, so equal declarations can produce affirmative assurance
for substantially unequal execution budgets.

**Proof:** actual inference clients sharing a fake model sent caps of 10 and 1000
and reported corresponding token usage. Both variants declared a cap of 10;
the report still returned `matching.max_output_tokens=True`.

**Fix:** bind/validate caps at dispatch, reject observed overflow, and distinguish
declared from verified equality. Missing usage is unknown, not verified equal.
This concerns experiment fairness, not the new runtime USD reservation ledger.

## P2 findings — core recovery and artifact correctness

### A07 — Async resume permanently skips unattempted fail-fast items

Source: `insideLLMs/runtime/_async_runner.py:416–420,492–499,686–689,753`.

Persisted skipped placeholders count as completed work during resume.
**Proof:** a three-item run called only `a,b`, failed on `b`, and persisted `c`
as skipped. Resume made no additional calls but changed `run_completed` from
false to true. Health remained unhealthy; this is not a healthy-CLI bypass.

**Fix:** safely replace/truncate the explicitly unattempted tail, or reject this
resume state clearly. Test both stored statuses and actual provider call counts.

### A08 — Structured-output probes cannot score their own resumed records

Source: `insideLLMs/runtime/_result_utils.py:580–586`;
`insideLLMs/probes/attack.py:855`; `insideLLMs/probes/bias.py:910–913`.

Reload produces mappings, while scorers expect typed result attributes.
**Proof:** Attack and Bias initial runs succeed; full resume raises
`AttributeError` for both sync and async, without additional model calls.
Manifests still report healthy/complete, also illustrating A04.

**Fix:** define validated, versioned output reconstruction or mapping-compatible
scorers. Test every structured-output built-in through full and partial resume.

### A09 — Ultimate upload precedes final local bundle contents

Source: `insideLLMs/runtime/_ultimate.py:259–292`.

**Proof:** the mocked push snapshot lacked `attestations/08.policy.dsse.json`,
`attestations/09.publish.dsse.json` and `integrity/bundle_id.txt`; all appeared
afterward. The remote input and final local tree therefore differ. Reusing a
directory could instead upload stale versions.

**Fix:** finalize prepublication evidence and content identity before upload.
Keep the resulting registry digest/publication receipt out of the self-hashed
payload or define a separate receipt layer; avoid circular self-reference.
Test membership and bytes at the push boundary, not just final local existence.

### A10 — LaTeX export does not escape untrusted text

Source: `insideLLMs/cli/commands/export.py:111–116`.

**Proof:** export retained active `\input{sentinel.tex}` and unescaped `&`, `%`
and `_`. No compiler ran. Ordinary text can break the table; a later compilation
can interpret model/dataset content as TeX, including file inclusion. Shell
command execution is not claimed.

**Fix:** escape headers and values after truncation. Any trusted raw-TeX mode
should be explicit. Test special characters and command-looking inputs.

### A13 — Report rebuilding discards interrupted-harness diagnostics

Source: `insideLLMs/cli/commands/report.py:62,69–79`.

The command derives a new summary solely from observed records and overwrites
`summary.json` without retaining the prior summary or manifest's incomplete-run
context.

**Proof:** an actual harness completed its first DummyModel cell, then failed
initializing an unknown second model and exited 1. Its summary recorded an abort,
unhealthy state, expected count 2, observed count 1, and `run_completed=false`.
The actual `report` command exited 0, generated HTML, and removed `abort`,
`health`, and `run_completed` from the summary. Its sole record was successful.
The manifest remained unchanged and incomplete: this is diagnostic loss, not
a manifest-based diff-gate bypass.

**Fix:** reconstruct reports with manifest health and expected coverage, preserving
abort/secondary diagnostics. Make incomplete status visible in generated output;
test rebuilding both completed and interrupted harness artifacts.
